# go-polar

Unofficial Go client for the Polar API, generated from the OpenAPI document Polar publishes. If you only want to use the client from an agent, read [.agents/skills/go-polar/SKILL.md](.agents/skills/go-polar/SKILL.md) instead; this file is about changing the code.

## Architecture

One generated package, `polar`, at the module root, driven by `gen.go`:

`scripts/fetch-spec.sh` selects and downloads the newest effective version from `polarsource/polar/docs/openapi` into `api/` → `scripts/patch-spec.sh` normalizes scalar-or-array query filters → oapi-codegen with `config.yaml` → `scripts/split-gen.sh` → `client_*.gen.go`.

Spec names have the form `YYYY-MM.openapi.json`. Compare each version to the current UTC month and select the greatest version that is no later than that month. A version becomes effective on the first day of its named month. Never select a future month, even if its file already exists upstream. Fail if no eligible version exists.

## Stack

- Go 1.26.9.
- oapi-codegen, pinned as a `tool` dependency in `go.mod`.
- Runtime: `github.com/oapi-codegen/runtime`.

## Layout

- `gen.go`, `config.yaml`, `client_*.gen.go`: the package.
- `client_test.go`, `example_test.go`: tests, including the README example.
- `scripts/`: spec download, query filter patch, generated-file splitting, lint and security scan scripts.
- `api/`: the downloaded spec, gitignored.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the spec and regenerate
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- The pinned generator reads OpenAPI 3.1 directly. Scalar-or-array query filters need the slice patch in `scripts/patch-spec.sh`; without it their anonymous union fields cannot be populated by callers.
- Split output is generated, including import cleanup. Never edit a part by hand.
- Empty JSON response schemas map to `json.RawMessage` through the spec patch. Keep this mapping so unspecified payloads retain their bytes instead of becoming arbitrary decoded trees.
- `skip-prune` retains all component schemas, including webhook payload types. The client does not verify webhook signatures. The patch also normalizes punctuation and provider pronouns in descriptions without changing wire data.
- Tax-ID response values are two-element JSON arrays. Their input counterparts can be strings. Preserve that distinction. Response tuples use `*[]interface{}` and do not enforce positional enum validation.
- Without the `number` to `float64` mapping in `config.yaml`, amounts become `float32`.
- Paths include `/v1`; client constructors take `https://api.polar.sh` or `https://sandbox-api.polar.sh` without a second `/v1` prefix.
- Authentication uses bearer tokens through a request editor. Customer and member session tokens are distinct from organization access tokens.
- Customer responses are discriminator unions. Use generated `AsCustomerIndividual` or `AsCustomerTeam` helpers to inspect them.
- Method names derive from operation IDs. `products:list` becomes `ProductsList`, and `customers:create` becomes `CustomersCreate`.
- Pagination uses a one-based `page`, `limit`, and response `pagination.total_count` and `pagination.max_page`.
- `make generate` downloads the newest effective spec, so it can change the client even when nothing here changed. Review the generated diff before releasing it.
- The source contains webhook schemas. This repository is a REST client, not a webhook server or WebSocket client.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When the checks fail, Claude edits the repository to fix them, but a fix may not touch the paths listed under `fix_protected_paths` in that workflow: the workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, the lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
